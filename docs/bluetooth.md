# 蓝牙连接指南

EchoLink 的蓝牙走的是**标准 SPP(串口)profile**,也就是 `00001101-0000-1000-8000-00805F9B34FB`。
好处是 Windows 与 Android 原生都支持,不需要在电脑上装任何蓝牙驱动或服务;代价是**必须先配对**,
而且同一时刻只能有一台设备占用这个串口。

> 局域网(TCP)更快,适合同 Wi-Fi 下传大文件;蓝牙适合"不在同一网络"或"不想开端口"的场景。

## 一、Windows 电脑端:让电脑"等"手机连进来

手机要连电脑,电脑这一侧必须是**传入(incoming)**的串口。

1. **打开蓝牙并配对手机**
   设置 → 蓝牙和其他设备 → 添加设备 → 蓝牙 → 选你的手机。
   手机上会弹出配对码,两边数字一致即确认。

2. **确认/添加传入串口**
   设置 → 蓝牙和其他设备 → 更多蓝牙设置 → **COM 端口** 标签页 → 添加 → 选"传入",选中你的手机。
   Windows 一般会在配对时自动建好,所以这一步常常只需要**确认列表里有这台手机**。

3. **找到端口号**

   ```bash
   python -m echolink ports
   ```

   ```
   设备          类型        说明
   COM4        蓝牙 SPP    蓝牙链接上的标准串行 (COM4)
   COM3        蓝牙 SPP    蓝牙链接上的标准串行 (COM3)
   ```

   类型列显示"蓝牙 SPP"的就是。注意一台电脑上可能有好几个(连过的每个设备各一个),
   挑**说明里带你的手机名**或刚刚新出现的那个。

4. **启动服务并启用蓝牙**

   ```bash
   python -m echolink server --bt COM4
   ```

   看到 `蓝牙串口 COM4 已就绪,等待手机连接…` 就成了。
   想同时保留局域网访问就**不要**加 `--no-tcp`;只走蓝牙就加。

   也可以写进 `server.json`,省得每次带参数:

   ```json
   "bluetooth": {"enabled": true, "port": "COM4", "baudrate": 115200, "auto_detect": true}
   ```

   把 `port` 留空并保持 `auto_detect: true` 时,服务端会自动挑一个蓝牙 SPP 端口(不确定是哪个时用)。

## 二、Android 手机端:连接电脑

1. 手机 设置 → 蓝牙 → 与电脑配对(和上面第 1 步是同一件事,任意一边发起都行)。
2. 打开 EchoLink App,在"连接目标"里填:

   ```
   bt:AA:BB:CC:DD:EE:FF
   ```

   `AA:BB:...` 是**电脑**的蓝牙 MAC 地址。App 里可以直接从"已配对设备"列表里点选,
   不需要手抄。

3. 填配对密钥(电脑启动时打印的那串),点连接。

底层的动作是:`BluetoothAdapter.getBondedDevices()` 找到电脑 → `createRfcommSocketToServiceRecord(SPP_UUID)`
→ 失败则退到 `createInsecureRfcommSocketToServiceRecord`(部分电脑的 SPP 服务不接受加密通道)。
连上之后就是一条裸字节流,和 TCP 完全一样。

## 三、命令行客户端走蓝牙(Windows → 电脑)

```bash
# 客户端在另一台 Windows 上,通过蓝牙串口连主机
echolink cli -t serial:COM5 -s <密钥> info

# 或者让它自己找蓝牙串口
echolink cli -t serial:auto -s <密钥> ls
```

`serial:COM5` 表示"打开这个串口当作链路",`bt:` 前缀是 Android 专用(RFCOMM),
在桌面系统上用 `serial:`。

## 四、排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `打开串口 COM3 失败: 信号灯超时时间已到` | 该端口对应的设备不在范围内/已关机 | 换另一个端口;或让手机先连上来再启动服务 |
| `打开串口失败: 拒绝访问` | 端口被别的程序占用(常见于串口调试工具) | 关掉占用程序;或重启蓝牙支持服务 |
| 手机一直"连接中" | 选错了端口(连到了另一个设备的 COM) | `echolink ports` 逐个试,或看说明里的设备名 |
| 连上后立刻断开 | 电脑端开了 `--no-tcp` 但手机填的是 Wi-Fi 地址 | 检查手机里填的是 `bt:MAC` 还是 `IP:端口` |
| 传输速度只有几十 KB/s | SPP 串口带宽限制(115200 波特率约 11 KB/s 有效) | 大文件改用局域网;或提高 `baudrate`(需两端一致) |
| App 提示无蓝牙权限 | Android 12+ 需要运行时授权 | 系统设置里给 App 蓝牙权限,或重装后首次启动时允许 |

## 五、关于带宽的实话

蓝牙 SPP 不是为传文件设计的。115200 波特率下有效吞吐大约 **11 KB/s**,一张 5 MB 的照片要 7 分钟以上
(实际上手机与 Windows 之间的 SPP 经常能协商到更高,但仍远低于 Wi-Fi)。

所以实际用法建议:

- **蓝牙**:控制类操作(静音、关机、截屏、看目录、改文件名)——数据量小,延迟可接受;
- **局域网**:传文件——同一 Wi-Fi 下能跑满几十 MB/s。

EchoLink 两种链路共用同一套协议,换链路只改连接目标字符串,命令和界面完全不用变。
